# V2.47 — Native Calendar view diagnostics

Release date: 2026-09-25

## Purpose

V2.47 is a diagnostic release for a Thunderbird built-in Calendar rendering issue where Microsoft 365 NATIVE events are complete in Day/Week but some events are missing in Month and in the upper row of a two-week Multiweek view.

## Changes

- NATIVE: record the real `calICalendar.getItems()` requests received by the M365 provider, including filter mask, count, requested range, timezone/date metadata and a bounded call history.
- NATIVE: run a non-destructive mirror query for bounded provider requests using Thunderbird's storage `getItemsAsArray()` when available, recording the result count and a bounded item summary (ID/title/start/end/recurrence metadata).
- NATIVE diagnostic ZIP: capture the currently open Thunderbird Calendar view, its visible range and selection.
- NATIVE diagnostic ZIP: compare the registered cached calendar wrapper with the underlying provider storage for the exact current view range using parent and occurrence filter masks.
- NATIVE diagnostic ZIP: attempt a read-only scan of rendered calendar item elements and export any attached occurrence/item objects, so backend-returned items can be compared with what the Month/Multiweek UI actually instantiated.
- NATIVE diagnostic ZIP: include `native_current_view.json` and `native_provider_queries.json` in addition to the existing Graph/cache/range-query material.
- GitHub updater: explicitly supports repository upgrades from V2.43, V2.44, V2.45 and V2.46 to V2.47, keeps `.git` untouched, backs up the previous tree and verifies the final managed payload by SHA-256.
- STANDARD/ATN runtime behavior is unchanged apart from the version increment.

## Diagnostic workflow

1. Reproduce the missing-event state in Thunderbird Month or Multiweek view.
2. Without navigating away, open the M365 Calendar Space.
3. Under Native integration, create the calendar diagnostic ZIP. The default date range already covers several weeks around the current date; adjust it only if the affected dates are outside that range.
4. Attach the resulting diagnostic ZIP together with a screenshot.

The diagnostic export contains calendar content and attendee addresses but intentionally excludes OAuth access and refresh tokens.
