# M365 Calendar for Thunderbird V2.46

V2.46 is a targeted NATIVE calendar-view refresh update built on the V2.45 release baseline. It addresses a reproducible display pattern where Microsoft 365 events can be present in Thunderbird's calendar backend and visible in Day/Week, while Month and the upper row of a two-week Multiweek view omit some events.

## Runtime change

- **GITHUB NATIVE / INTERNAL NATIVE:** the add-on now prefers Thunderbird's item-level `refreshItems(true)` operation for open Calendar views. This forces the view to re-query calendar items without intentionally changing the selected day or visible date range.
- A guarded legacy `goToDay()` fallback remains for Thunderbird versions where the item-refresh method is unavailable.
- View-refresh diagnostics now capture the view ID/type, visible range, selected day, refresh strategy, result and elapsed time.
- Graph event mapping, native-cache event mapping and synchronization semantics are intentionally unchanged.

## STANDARD / ATN

The STANDARD runtime is unchanged apart from the version increment. The ATN artifact remains the Experiment-free STANDARD edition and contains no custom `experiment_apis` entry and no `experiments/` directory.

## Diagnostic intent

If Month/Multiweek still omits an event while diagnostics show that Graph, native cache and Thunderbird range queries contain it, the remaining defect is isolated much more strongly to Thunderbird's Calendar view/rendering layer. That evidence is suitable for a focused upstream Thunderbird bug report.

## Compatibility

- Add-on version: `2.0.46`
- Display release: `V2.46`
- Minimum Thunderbird: `128.0`
- ATN STANDARD: no `strict_max_version`
- GitHub NATIVE: no artificial maximum version; ESR remains recommended for production use because the Experiment API depends on Thunderbird internals.
