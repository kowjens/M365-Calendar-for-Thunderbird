# M365 Calendar for Thunderbird V2.42

V2.42 focuses on **split-mail deployments** where ordinary email remains at a third-party host (for example one.com) while Microsoft 365 / Exchange Online remains authoritative for Teams and calendar processing.

## Changes

- Adds a NATIVE external-iMIP fallback for invitations received through a non-Microsoft IMAP account when no corresponding Exchange event can be found.
- The fallback creates a **personal Microsoft 365 calendar copy without attendees**. It never recreates the external attendee list, so it cannot accidentally turn the attendee into the organizer of a new meeting.
- Marks the fallback operation so Thunderbird uses its normal iMIP email transport for the attendee RSVP instead of suppressing the reply as a Graph-owned Exchange operation.
- Adds an explicit NATIVE setting: **External email invitation fallback (iMIP → personal M365 copy)**. It is disabled by default in public builds and enabled by default in the supplied INTERNAL NATIVE build.
- Replaces generic `0x80004005 / NS_ERROR_FAILURE` behavior for an unmatched external invitation with a specific, actionable error when the fallback is disabled.
- Keeps the normal, preferred path unchanged: if Exchange already owns the invitation, Accept/Tentative/Decline uses the matching Graph event and Graph RSVP endpoint.
- Retains the Thunderbird 154+/156 native startup fix from V2.41.
- Reorganizes GitHub documentation and adds dedicated Microsoft Entra application-registration and one.com/Exchange calendar-relay guides.

## Recommended split-mail architecture

For production, the add-on fallback is a safety net rather than a replacement for server-side calendaring delivery. Microsoft documents a third-party-mail architecture in which the existing MX remains at the current mail provider, incoming mail is dual-delivered/forwarded to Exchange Online, and an Exchange transport rule removes all externally forwarded messages except the `Calendaring` message type. This allows normal mail to stay at the third-party provider while meeting requests/responses reach Exchange Online and therefore the Microsoft 365 calendar.

See `docs/setup/ONECOM_EXCHANGE_CALENDAR_RELAY_DE.md` and `docs/setup/MICROSOFT_ENTRA_SETUP_DE.md`.
