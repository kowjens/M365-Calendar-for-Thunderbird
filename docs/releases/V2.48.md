# V2.48 — Thunderbird Month/Multiweek known-issue documentation

Release date: 2026-09-25

## Purpose

V2.48 is a documentation and release-hardening update following the V2.47 deep diagnostic capture of the NATIVE Month/Multiweek missing-event symptom. It does not introduce another calendar-mapping or GUI workaround.

## Diagnostic conclusion

In the reproduced Thunderbird 153.3.1 failure state:

- Microsoft Graph and Thunderbird native cache contained the same 35 events in the diagnostic range.
- `missingNative = 0`, `nativeOnly = 0`, and no recurring series showed missing native instances.
- For the exact visible two-week Multiweek range, the cached calendar wrapper, underlying provider and offline storage each returned the same five Microsoft 365 events.
- The same five events were also found as instantiated `calendar-month-day-box-item` objects in the Thunderbird Month/Multiweek DOM diagnostic.
- Day/Week displayed the same calendar data correctly while Month/Multiweek could omit entries visually.

This evidence moves the remaining failure boundary downstream of Graph synchronization and the add-on's provider/cache mapping, into Thunderbird Calendar frontend item layout/painting or adjacent host-UI processing. The project therefore documents it as a known Thunderbird-side rendering limitation pending upstream resolution.

## Changes

- Keep the V2.47 provider/range/current-view diagnostics unchanged and available in NATIVE.
- Add `docs/KNOWN_ISSUES.md` with scope, evidence, practical workarounds and related upstream bugs.
- Update README, troubleshooting and GitHub publishing text so users are not led to expect Month/Multiweek NATIVE rendering to be fully reliable on affected Thunderbird builds.
- Prepare a fully anonymized public-safe Bugzilla evidence package from the reproduced V2.47 diagnostic capture.
- GitHub updater supports direct updates from V2.43 through V2.47 to V2.48 and preserves `.git`.
- STANDARD/ATN runtime behavior is unchanged apart from the version increment.

## Scope

The issue concerns the **GITHUB NATIVE** edition using Thunderbird's built-in Calendar. The ATN/GITHUB STANDARD editions use the add-on's own Microsoft 365 Space and do not register the custom native calendar provider.
