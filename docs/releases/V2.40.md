# M365 Calendar for Thunderbird V2.40

## Publication hardening

V2.40 prepares the V2.39 code line for a cleaner GitHub/ATN publication without changing Microsoft Graph synchronization semantics.

- Fixed malformed literal `\n` tokens in `calendar/calendar.css` (STANDARD and NATIVE). These tokens could make the validator parse the following CSS as malformed/nested selectors.
- Added a regression test that rejects literal escaped-newline tokens in the calendar stylesheet.
- Fixed the GitHub Actions XPI build step: `python tools/build_xpi.py --all` and `python tools/build_xpi.py --atn` now execute as two commands in a YAML block.
- GitHub NATIVE builds remain uncapped (`strict_max_version` omitted) so Monthly releases can continue to be tested.
- The ATN NATIVE package intentionally remains capped at `156.*`, because Thunderbird's Experiment-specific linter requires `strict_max_version` for accepted Experiment submissions.
- ESR remains the recommended production/business channel.
- All V2.34–V2.39 Teams, RSVP, outgoing-message confirmation, reminder-safety, diagnostics and compatibility behavior remains unchanged.

This is a packaging/validation release; it does not intentionally change calendar data handling or Graph write behavior.
